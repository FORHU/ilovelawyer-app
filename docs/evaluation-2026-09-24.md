## 1. ~~Possible~~ XSS in the spreadsheet preview — FIXED 2026-09-28

**Resolution:** confirmed exploitable, then fixed. `xlsx-preview` 1.0.5 escapes nothing — hyperlink addresses go into `href` raw, rich text and formula results go in as markup, font names go into `style` (`src/htmls/genText.ts`, `genCell.ts`). Every sheet now goes through `lib/chat/sanitize-sheet-html.ts` (DOMPurify, plus: external images dropped, `url(` in inline styles dropped, links forced `rel="noopener noreferrer"`) before it is stored in state. Tests with the crafted payloads are in `lib/chat/__tests__/sanitize-sheet-html.test.ts`. Original finding kept below for the record.


`apps/web/components/chat/attachment-preview.tsx:343` injects HTML generated by `xlsx-preview` from an uploaded `.xlsx` via `dangerouslySetInnerHTML`, with no sanitizing.

- Whether it's exploitable depends on whether `xlsx-preview` escapes cell text. If it doesn't, a cell containing `<img src=x onerror=...>` runs script in the viewer's session.
- **This matters more now:** in the desktop app, pages can call the Tauri shell's commands, so a script injected here could also open windows — and, since Window Intelligence (`current_dock_target` / `dock-target-changed`), read the title of whatever other app's window the user was last in. Those titles carry client names and medical records.
- **Fix:** run each sheet's HTML through DOMPurify before rendering. That settles it regardless of how the library behaves.
