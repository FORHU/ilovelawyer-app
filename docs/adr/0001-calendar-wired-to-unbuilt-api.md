# Calendar planner is wired to a not-yet-existing API, not local storage

The Calendar page's planner (Appointments, Notes) is built against real `POST`/`GET /api/appointments` and `/api/notes` calls via `apiFetch` and React Query, the same way `Case` (`apps/web/lib/cases/mutations.ts`) is wired to `POST /api/cases` before that endpoint existed. We considered persisting to `localStorage` instead so the feature would actually work end-to-end before the backend ships, but rejected it: this repo has no existing client-only persistence pattern for domain data, and introducing one here would mean ripping it out and re-wiring to the real API later. Following the Case precedent keeps one persistence pattern in the codebase, at the cost of Appointments/Notes not actually saving until `ilovelawyer-api` implements the endpoints.
