# UI translation uses static, manually-translated catalogs — not Google Translate, an LLM, or locale-routing

The Display Language feature (English/Korean/Tagalog dropdown switcher) is built on `i18next`/`react-i18next` with static, per-feature JSON Language Catalogs, translated by hand, with the Language Preference persisted to `localStorage` only. We considered three alternatives and rejected each. Calling Google Translate (or any live translation API) at runtime was rejected as the explicit starting motivation for this work — it means an ongoing vendor dependency (API keys, quotas, cost, and translation-quality drift over time) for content that doesn't actually change once written. Generating the catalogs once via an LLM and checking them in was considered as a middle ground — it would have kept the "no runtime vendor" property — but manual translation was chosen instead so a human reviews every string before it ships, given translation quality directly affects how the app reads to Korean- and Tagalog-speaking users. `next-intl`'s locale-prefixed routing model (`/ko/homepage`) was rejected in favor of `react-i18next`'s non-routing mode, since this app has no existing locale-in-URL pattern and the feature was specced as a plain toggle, not a route change — adopting `next-intl` would have meant introducing middleware and route restructuring solely for this. Syncing the Language Preference to the user's backend account (so it follows them across devices) was rejected for now in favor of local-only `localStorage`, matching the existing Remember Session pattern, because the account-level version requires a change in the separate `ilovelawyer-api` repo that this build doesn't touch. The cost of these choices: Korean and Tagalog Language Catalogs will lag English as new UI ships (every new string is English-only until someone manually translates it, silently falling back to English in the meantime), and the Language Preference won't follow a user who switches devices until a future backend-synced version is built. Translation of legal document content and AI chat responses is out of scope entirely — see `CONTEXT.md`'s Pending section.
